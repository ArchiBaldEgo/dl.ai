# CLAUDE.md

Django + Channels (Daphne) app mounted under `/ai/` on the same domain as `dl.gsu.by`.
DLSID cookie authentication is delegated to dl.gsu.by via `EXTERNAL_AUTH_API_URL`
(local users auto-provisioned). The default-active model catalog is **Ollama**
(cloud models via `OLLAMA_HOST`/`OLLAMA_API_KEY`) + **OpenRouter** (`OR_*` free models
via `OPENROUTER_API_KEY`) + the **Web DeepSeek** and **Web Kimi** Puppeteer bot-pools
(`Web_DeepSeek[_Thinking]` / `Web_Kimi`, OpenAI-compatible pool APIs in the same container
on :3000 / :3001). Groq and SambaNova are registered only when `AI_ENABLE_GROQ` /
`AI_ENABLE_SAMBANOVA` are set (default off) — flip in `.env` to activate.

> **Deep gotchas live in skill `dlai-code-map`.** Routing map + canonical docs → `SKILL.md`;
> детальные гочхи по областям (визард, права админки, arm_runner, карвер, пулы, ops) →
> `gotchas-deep.md` рядом с ним. Инвоукни skill при старте работы в незнакомой области.
> Ниже — только daily-критичные правила.

## Fundamental principles (OOP / SOLID / DRY / KISS)

- **Polymorphism over branching.** New chat modes = `ModeMessageBuilder` subclasses
  (`ai/services/message_composer.py`) registered in `_MODE_BUILDERS` — never an
  `if type == …` ladder in the consumer. New models within a provider = one row in the
  declarative table (`GROQ_MODELS`, `OLLAMA_MODELS`, `OPENROUTER_FREE_MODELS`,
  `SAMBANOVA_MODELS`) + one `_MODELS` entry in `registry.py` — handlers generated by
  `make_table_handlers`. Keep the table↔registry parity test
  (`tests.py::test_ollama_table_and_registry_in_sync`) green — it guards this rule.
- **DRY.** Import, don't copy. Canonical owners:
  - grading/answer comparison → `ai/grading.py` (deterministic difflib, no LLM-judge);
  - prompt visibility: all prompts visible READ-ONLY to every admin entrant (baseline
    `page.prompt_admin_all`); overwriting someone else's prompt is gated by
    `page.prompt_admin.edit_others` (`PromptAdmin._can_edit_prompt`). Chat-facing APIs
    (`get_problem_data`, `get_prompts`) list ALL prompts — preprompts are student content;
  - DLSID session-id → `ai/http_utils.py::resolve_dl_session_id`;
  - DL exception → JSON error → `ai/dl_api_client.py::dl_error_response`;
  - extension → language → `ai/services/task_registry.py::EXTENSION_TO_LANG` (only copy;
    `.i86` и `.asm` = «Ассемблер i8086»);
  - HTTP headers/Puppeteer-пул-протокол → `ai/model_clients/_base.py` (`bearer_headers`,
    `proxy_bypass_session`, `make_table_handlers`, `BotPoolClient`); `web_deepseek.py` /
    `web_kimi.py` — тонкие конфиги, новый web-пул = конфиг, не копия;
  - identity для `AIRequestLog` → `ai/services/auth.py::get_user_identity_for_log`;
  - DL verdict из комментария → `ai/dl_api_client.py::dl_verdict_from_comment`
    (fail-маркеры приоритетнее success; нераспознанное → failed);
  - кэш решённых задач → `ai/services/solution_cache.py` (`TaskSolution`) —
    детальные правила записи/отдачи в gotchas-deep;
  - identity `AIRequestLog`/`get_user_identity_for_log` см. выше; capability-метаданные
    (Text/Vision/Reasoning) живут в `registry.py`, НЕ в DB.
- **Encapsulation.** `ConversationHistory.get()` — defensive copy, не мутировать;
  персист только `append()`.
- **KISS/YAGNI.** Нет мёртвых модулей/флагов/констант — незарегистрированный провайдер
  удалить (см. легаси gigachat/huggingface), секрет без консьюмера не нужен в config.py.
- **Layering (SRP).** Consumers orchestrate; services execute (`ai/services/`); admin views
  guard permissions and render; runners (`arm_runner`, `test_console_runner`) own payloads.
  Бизнес-логику в `consumers.py`/вьюхи не пушить.

## Module map

- `views.py` — page views + API endpoints (`/ai/api/*` wired in `DjangoTest/urls.py`);
  `asset_view` (HTTP revalidation, dev-bypass гочхи), `_render_ai_page` (self-heals model
  availability через `trigger_model_health_refresh_async()`); wizard-конфиги страниц.
- `consumers.py` — Channels WS consumer (`/ai/chat/ws/<client_id>`, `routing.py`); thin
  orchestrator over `services/`; legacy aliases resolved in `ModelCaller`.
- `models.py` — capability-метаданные не тут (см. registry).
- `serializers.py` / `i18n.py` — лёгкие сериализаторы + tri-язычный UI (RU/EN/FR).
- `middleware.py` — `ExternalAuthMiddleware` (DLSID → session cache `AI_AUTH_CACHE_TTL`,
  фолбэк на последний кэш при падении dl.gsu.by, 503 только без кэша и не optional path) +
  `CsrfSessionFallbackMiddleware`; реальная логика — `ai/external_auth.py` (переиспользуется
  WS-auth service).
- `http_utils.py` — `safe_relative_url` (open-redirect guard), `resolve_dl_session_id`.
- `dl_api_client.py` — DL REST client + flow «Тестирование» (`/ai/api/send-solution/`).
- `external_account.py` — создаёт/апдейтит Django users + `ExternalDLAccount`;
  зачисляет всех в `prompt_developer`; `auth_backends.py` — внешний admin backend.
- `throttling.py` — per-user rate limiting (120 WS / 200 HTTP per 60s; `AI_WS_RATE_LIMIT`,
  `AI_HTTP_RATE_LIMIT`, `AI_HTTP_POLL_RATE_LIMIT` — отдельный повышенный для polling-эндпоинтов).
- `admin/` — custom `ai_admin_site` at `/ai/admin/`; per-module views тут, core permission
  logic в `site.py`. Права страниц (baseline-модель), «Посмотреть как…», доска «Таски» —
  gotchas-deep.
- `test_console_runner.py` — runner тест-консоли (subprocess `manage.py test ai
  --settings=DjangoTest.test_settings`; логи в `BASE_DIR/logs/test_console/`). Log filenames
  validated `_LOG_FILENAME_RE` (path-traversal barrier).
- `model_clients/` — `registry.py` (id → handler/title/capabilities), `_base.py`
  (`BotPoolClient` — весь Puppeteer-пул-протокол), `web_deepseek.py`/`web_kimi.py` (тонкие
  конфиги), `config.py` (.env tokens/proxy), `exceptions.py` (`humanize_model_error`,
  `map_http_error`), `history.py` (`ConversationHistory`), провайдеры
  `groq.py`/`openrouter.py`/`sambanova.py`/`ollama.py`.
- `arm_runner.py` — async ARM runner; in-memory live job, DB (`AIModelTestRun`/`Result`)
  source of truth; батч-солв, перезапуски пар, карвер кода — gotchas-deep.
- Журнал запросов — `ai/admin/request_logs.py` (`/ai/admin/ai/request_logs/`;
  `request_logs.html` скелет + партиал `request_logs_table.html`, AJAX меняет обёртку
  целиком; JS на делегировании).
- Онбординг-wizard — `ai/services/onboarding.py` + движок `static/admin/js/ai-wizard.js`;
  правило «каждый видел тур», бамп `WIZARD_VERSION` — gotchas-deep.
- Templates: `ai/templates/ai/` (юзер-страницы), `ai/templates/admin/ai/` (админка); статик
  в `static/admin/js/`: `chat_template.js` (только чат), `decide_task.js`/`find_error.js`
  self-contained, `ai_processes.js` (меню «Процессы» через `admin/base_site.html`),
  `test_console.js`.
- Root-level: `WebDeepseek/` (:3000), `WebKimi/` (:3001, отдельный `KIMI_*` env; login через
  `seed.js`), `REST API.md`, `DOCX.md`, `test_arm_solve.py`, `mail_bridge.py` /
  `backup_runner.sh` / `health_check.sh` (email→ops bridge). `bot/` — LEGACY, не
  референсится кодом.

## Critical gotchas (daily)

- Named form fields shadow DOM: `form.action` при `<input name="action">` возвращает INPUT,
  не URL → 404; читать через `form.getAttribute('action')` (`FormActionShadowingTests`).
- Шаблоны: `{# … #}` только в одну строку; многострочный — `{% comment %}…{% endcomment %}`
  ПОСЛЕ `{% extends %}` (`TemplateInlineCommentTests`).
- `serialize_topic` отдаёт язык под ключом `programming_language` (не `..._id`) — клиентские
  фильтры тем читают `t.programming_language` (`ArmFindErrorTopicsKeyTests`).
- AJAX админки ждёт JSON: протухшая сессия → HTML логина; все хендлеры через локальный
  `parseJsonResponse(response)` («Сессия истекла…», не JSON.parse error).
- Базовые колонки `Prompt.prompt_name`/`prompt_text`, `SharedPrompt.*`, `Topic.topic_name`
  удалены из БД (миграции 0041/0042 → `*_ru`); единственная локализация — `ai/i18n`
  (`get_localized_name/text`); пустые `*_ru` → без RecursionError (см. gotchas-deep).
- `RateLimitMiddleware` уже считает каждый `/ai/` HTTP — не вешать ещё `@rate_limited`
  на эти вьюхи (double-counts).
- `threading.Lock` раннеров (`_jobs_lock`) нереентерабельный — не вызывать
  `_append_log`/`_update_job` внутри `with _jobs_lock` (deadlock).
- Мутации чата: `ConversationHistory.get()` — копия; Redis-кэш тоже отдаёт копию —
  писать только `append()`.
- Персистенция чата в localStorage (`ai_msgs_…`): реплей через `ws.onmessage` глушится
  `_restoringPersistedMessages` (иначе история удваивается); аккордеоны/карточки ARM сами
  не раскрываются.
- Тесты на RequestFactory: не ставить `CSRF_COOKIE` вручную (маскировка — строгий алфавит,
  «test-token» падает `ValueError`); admin-view POST JSON — `content_type="application/json"`.
- Скорость changelist'ов: `show_facets = admin.ShowFacets.NEVER` во всех ModelAdmin
  с `list_filter`. Не возвращать.
- Старт процесса → `document.dispatchEvent(new Event('ai-processes:refresh'))`
  (ai_processes.js подхватывает мгновенно, не ждёт 15-сек тик).
- Escape любого user/model HTML перед `innerHTML` (think-блоки модели отдают сырыми).
- `MOSCOW_TZ` из `ai/constants.py` + `timezone.localtime()`; никогда не хардкодить
  `+ timedelta(hours=3)`.
- Model selector: топ-1 фаворит юзера (`_get_user_top_model_keys`, gated `AIAppSettings.
  favorites_epoch`) первой, дальше строго алфавит по title.

## Update log / git hooks

- `sync_update_log` не-интерактивно в Dockerfile CMD; `post-merge`/`pre-push` hooks
  (`scripts/setup_hooks.sh`) зовут с `--interactive` (docker `exec -it`); без TTY НЕ импортирует
  ничего. Невыбранные коммиты → `hidden=True` (управляются супер-only `UpdateLogAdmin`);
  merge-коммиты никогда не импортируются (`--rebuild` purge'ит и реимпортирует). Raw git nick →
  «ФИО (группа)» резолвится при рендере через `AuthorAlias` (правка алиаса чинит прошлые
  строки ретроактивно). Детали — gotchas-deep.

## Web bot-pools (ops)

- Оба пула в одном контейнере (стартует Dockerfile CMD): `WebDeepseek/` :3000, `WebKimi/` :3001
  (Kimi login сажается вручную в persistent Chrome profile — `WebKimi/seed.js`). Держать на
  127.0.0.1/internal; Docker healthcheck опрашивает :8000/health И оба пула
  (`ready_count > 0`).
- Правки пулов/воркеров живут ТОЛЬКО после рестарта контейнера. Краш рендерера — зомби-бот
  (`page.isClosed()` остаётся false!) — `_pageCrashed` + reap; конкуренция за бота ждёт до
  `queueWaitMs` (30с, env `BOT_POOL_QUEUE_WAIT_MS`/`KIMI_POOL_QUEUE_WAIT_MS`) — держать
  ЗАВЕДОМО меньше 300s-HTTP-таймаута Django-клиента. Анти-выкусывание/robust-фолбэк/эхо-гейт
  `promtps.js` — gotchas-deep. Мёртвый пул (0 ботов) диагностируется честным «пуст» по
  `/health` (`BotPoolClient.pool_state()`), не ask-пингом.
- Web-пулы down → health-check авто-рестартит пул и перепроверяет раз; gated
  `AI_WEB_DEEPSEEK_AUTORECOVERY`/`AI_WEB_KIMI_AUTORECOVERY` (default on).

## Tests

`python manage.py test ai` (DB-backed suite — требует Postgres-сервис `db` из docker-compose;
зелёный только с `DjangoTest.test_settings`).

Management-команды (см. `--help`):
- `auto_translate` — Google/deep-translator заполнение пустых `*_en`/`*_fr`
  (`--model`, `--overwrite`, `--lang fr`, `--dry-run`).
- `translate_prompts` — LLM-перевод Prompt/SharedPrompt через зарегистрированный хендлер
  (заполняет пустые, `--overwrite`).
- `reset_favorites_epoch` — сбрасывает топ-1 фаворитов всех юзеров (логи не удаляются).
- `reset_model_stats` — deletes all `AIModelStats` (cumulative avg-seconds/percent-solved
  в суффиксах селектора). После смены семантики duration: duration пары = ТОЛЬКО вызов
  модели, не DL-поллинг/лока. Скоупы stats (модель×язык×тема + легаси) — gotchas-deep.
- `delete_arm_run` — удаляет один batch-прогон из БД (+вычит вклада пар из `AIModelStats`);
  `--list`, `--yes` (иначе dry-run), `--drop-solutions` (заодно решения кэша прогона).
- `reextract_arm_codes` — ретро-переизвлечение кода старых прогонов (DL не перепроверяется).

## Security baseline

- No `@csrf_exempt` without strong authentication (e.g. `transcribe_audio` requires auth).
- Escape think-block HTML before `innerHTML`.
- No `verify=False` for HTTPS in production — `SKIP_SSL_VERIFICATION` local-dev only.
- Admin set-password flow принимает `external_user_id` только после
  `ExternalAuthMiddleware` + `_session_matches_external_id`.
- Не экспортировать `WebDeepseek/` (:3000) / `WebKimi/` (:3001) в публичные сети.
- Промпт-листинги админки/чата: all prompts read-only всем допущенным (student content);
  правка чужого — только ключ `page.prompt_admin.edit_others`.
