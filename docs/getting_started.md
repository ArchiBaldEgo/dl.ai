# Запуск dl.ai с нуля (для новичка)

Всё, что нужно человеку, который впервые открыл этот проект. Путь проверен: Windows 10/11 → WSL2 → Docker → приложение работает **без кук и без dl.gsu.by** (автоматический дев-логин).

Время: первый раз ~30–40 минут (большая часть — скачивание: Docker-сборка качает Python, Node, браузер Chromium и пакеты).

Весь проект живёт **в одном комплекте Docker**: и локальный запуск, и боевой сервер используют одни и те же `docker-compose.yml` + `Dockerfile`. Режим выбирается сам — по единственному признаку: **если в файле настроек `.env` прописан прокси, это прод; если прокси там пустой или его нет, это локальный режим** (правило зашито в `ai/env_mode.py`).

---

## Шаг 1. WSL2 (Windows → Linux-подсистема)

1. Откройте **PowerShell от администратора** (Пуск → наберите «PowerShell» → правая кнопка мыши → «Запуск от имени администратора»).
2. Выполните:

```powershell
wsl --install
```

3. Перезагрузите Windows (Пуск → «Завершение работы» → «Перезагрузка»).
4. После перезагрузки откроется окно Ubuntu: придумайте имя пользователя и пароль (это пароль Linux-подсистемы, не Windows; при вводе символы не отображаются — это нормально). Если окно не открылось — Пуск → наберите «Ubuntu».
5. Обновите пакеты (окно терминала, которое откроется, — это и есть ваш рабочий терминал):

```bash
sudo apt update && sudo apt -y upgrade
```

## Шаг 2. Docker

В терминале WSL (Ubuntu/Debian — команды одинаковые):

```bash
sudo apt update
sudo apt install -y docker.io docker-compose
sudo systemctl enable --now docker
sudo usermod -aG docker "$USER"
```

Потом **закройте терминал и откройте новый** (или выполните `newgrp docker`) — команда `docker` должна работать без sudo:

```bash
docker version
```

Если видите версии клиента и сервера — готово. Если `permission denied on /var/run/docker.sock` — вы не перезакрыли терминал (см. FAQ).

> Если у вас не Ubuntu/Debian — поставьте Docker по официальной документации вашей системы (https://docs.docker.com/engine/install/). Команда `docker compose` должна существовать без sudo.

## Шаг 3. Код проекта

В терминале WSL:

```bash
sudo apt install -y git
git config --global user.name "Ваше Имя Фамилия"
git config --global user.email "ваш.email@example.com"
git clone https://github.com/ArchiBaldEgo/dl.ai.git
cd dl.ai
```

Репозиторий публичный — доступы не нужны.

**Своя ветка** (ваш рабочий вариант кода, «привязанный» к main):

```bash
git switch -c my-feature        # создаст ветку с вашим именем
```

Так вы работаете в своей ветке и НЕ меняете main. Чтобы подтянуть чужие изменения:

```bash
git fetch origin
git rebase origin/main
```

> Храните проект в домашней папке WSL (`~/dl.ai`), а не на `/mnt/c/...` / `/mnt/d/...` — доступ к дискам Windows из Linux заметно медленнее, а Docker на таких папках тормозит.

## Шаг 4. Файл настроек `.env`

`.env` — это файл настроек проекта (в git не попадает). Создаётся за две команды:

```bash
cp .env.example .env
sed -i "s/^SECRET_KEY=$/SECRET_KEY=$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')/" .env
```

Теперь откройте его в простом редакторе:

```bash
nano .env
```

Навигация: стрелки-курсоры; вставка текста из буфера — правой кнопкой мыши; сохранить и выйти — `Ctrl+O`, затем `Enter`, затем `Ctrl+X`.

Впишите две строки (значения запросите у владельца проекта — они у каждого свои):

```
OLLAMA_API_KEY=...ваш ключ...
OPENROUTER_API_KEY=...ваш ключ...
```

Всё остальное менять **не нужно**. В частности, НЕ заполняйте строки `HTTP_PROXY=`, `HTTPS_PROXY=` — пустой прокси означает «это локальный запуск», и все остальные локальные удобства приложение включит само. Заполненный прокси означал бы «это боевой сервер» — но на вашем компьютере прокси, как правило, из WSL недостижим и всё сломает.

## Шаг 5. Запуск (одна команда)

```bash
docker compose up -d --build
```

Первая сборка занимает 10–20 минут: скачивается python-образ, пакеты, Node.js, Chromium. Дальше код меняется быстрее — пересборка качает только изменённое.

Что команда делает: собирает образ, поднимает вместе базу PostgreSQL, Redis, сайт (порт 8000) и nginx (порт 8080), автоматически выполняет `migrate` и `collectstatic` (локальный режим делает это за вас при старте).

Проверить, что контейнеры живы:

```bash
docker compose ps
```

Норма: у `web` статус Up (healthy) через 2–3 минуты после старта (healthcheck может помечать unhealthy в первые минуты — это период прогрева; подождите).

## Шаг 6. Откройте приложение

В браузере Windows: **http://localhost:8000/ai/chat/**

Вы автоматически вошли под пользователем `dev_admin` (суперпользователь) — без кук, без dl.gsu.by. Админка: **http://localhost:8000/ai/admin/** — доступна полностью.

Ещё вариант адреса — через nginx: http://localhost:8080/ai/chat/ (отличие: статика отдаётся nginx'ом, как на проде).

Проверка без браузера (в терминале):

```bash
curl http://localhost:8000/health
```

Должно вернуть `{"ok": true}`.

## Шаг 7. Автотесты (необязательно, но полезно)

Полный тест-сьют крутится внутри контейнера (несколько минут):

```bash
docker compose exec -T web python manage.py test ai --settings=DjangoTest.test_settings
```

Ожидаемый итог: `OK` (примерно 480 тестов). `skipped=1` — нормально.

## Как обновить проект (после чужих коммитов в main)

```bash
git fetch origin
git rebase origin/main
docker compose up -d --build     # пересоберёт и перезапустит
```

Остановить всё: `docker compose down`. Посмотреть логи сайта: `docker compose logs -f web`.

## Что локально НЕ работает (это не поломка)

| Фича | Почему | Что видите |
|---|---|---|
| «Реши задачу» / «Тестирование» на dl | нужна живая сессия dl.gsu.by (кука DLSID) | «sessionId обязателен» / «Нет DLSID» |
| ARM-пакетное решение | нужен DLSID | «Нет DLSID — требуется авторизация на dl.gsu.by» |
| Модели `Web_DeepSeek`, `Web_Kimi` | бот-пулам нужен ручной seed-логин | «Ошибка подключения…» |
| Ollama/OpenRouter без ключей | в `.env` не вписаны ключи | «нет доступных моделей» — впишите ключи (Шаг 4) |

Пустой список моделей после первого открытия страницы — подождите 1–2 минуты и обновите: страница сама запускает проверку моделей.

## FAQ (если что-то не так)

| Симптом | Причина / решение |
|---|---|
| `permission denied … docker.sock` | Не применилась группа: закройте и откройте терминал заново (или `newgrp docker`) |
| Сборка/запуск лезет в `10.1.1.57` и умирает (`i/o timeout`) | В вашем `.env` заполнены строки прокси (`HTTP_PROXY=` и др.) — на локальной машине они должны быть ПУСТЫМИ (закомментируйте `#`), затем `docker compose up -d --build` |
| Постоянный редирект на dl.gsu.by из браузера | Признак прод-конфигурации: те же пустые прокси в `.env` |
| Порт 8000/8080 занят | Рядом запущен другой стек: `docker compose down` в его папке; либо смените порт nginx строкой `AI_NGINX_PORT=9080` в `.env` |
| `web` долго unhealthy | Первые минуты — прогрев (healthcheck ждёт до 180 с). Дольше 5 минут — смотрите `docker compose logs web` |
| В чате «Ошибка: сессия истекла» | Обновите страницу и повторите |
| Сайт открывается, но без стилей (голый текст и ссылки) | Контейнер работает, но видит старый код: `docker compose restart web` (код проекта примонтирован, пересборка не нужна) |
| Ссылки на `/ai/assets/…` отдают «403 Authentication required» | Запрос без входа в приложение. Откройте сначала http://localhost:8000/ai/chat/ (вход происходит автоматически), потом обновите страницу с файлами |
| Список моделей пуст долго (>5 мин) | Нет ключей моделей в `.env` — см. таблицу выше |
