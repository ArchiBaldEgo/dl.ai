# Разработчику препромпта «В чём ошибка»

Эта глава — для тех, кто пишет и отлаживает препромпты режима
**«В чём ошибка?»**. Здесь нет пользовательской инструкции: как студент
открывает страницу, написано в `DOCX.md`. Здесь — как устроен промпт, где он
лежит, как его проверить на базе ошибочных программ и как читать метрики.

---

## 1. Как собирается сообщение модели

Режим «В чём ошибка» (`type=3`) собирает сообщение в
`ai/services/message_composer.py::FindErrorModeBuilder`:

```text
[общий (shared) промпт режима find_error]
        +
[условие задачи]
        +
[код студента]
        +
[выбранный промпт: «Промпт: …»]
        +
[инструкция «отвечай на языке пользователя», если UI не русский]
```

Важно:

- **Общий промпт** — одна запись `SharedPrompt` с `mode="find_error"`. Она
  задаёт базовую роль и формат ответа для ВСЕХ задач режима.
- **Выбранный промпт** — обычная запись `Prompt` с `mode="find_error"`,
  привязанная к языку и/или теме. Именно её студент выбирает в селекторе
  «Промпт». Она добавляется ПОСЛЕ условия и кода — модель видит её последней.
- Общий промпт не перезаписывайте под конкретную тему: он общий. Тематические
  правила живут в `Prompt`.
- Промпт не должен пересказывать условие или код: он задаёт ПРАВИЛА проверки.

---

## 2. Где лежит текст и как его установить

Source of truth для production-промпта:

```text
docs/prompts/find_error_cmpa_arrays.ru.txt
```

Команда установки (создаёт `Prompt`, по умолчанию НЕ перезаписывает
существующий — правки в админке канонические):

```bash
python manage.py seed_find_error_prompt --language "C-MPA"
```

С темой (рекомендуется, чтобы промпт подставлялся только для этой темы):

```bash
python manage.py seed_find_error_prompt \
  --language "C-MPA" --topic "Одномерный массив"
```

Полезные флаги:

| Флаг | Что делает |
|---|---|
| `--force` | Перезаписать текст существующего промпта из файла. |
| `--dry-run` | Показать план, ничего не записывая. |
| `--bind` | Создать/обновить `ArmPromptBinding` — промпт по умолчанию для ARM. |
| `--name "…"` | Другое название промпта. |
| `--file "…"` | Другой файл с текстом. |

Если команда пишет «Язык не найден» — сначала заведите язык
(`/ai/admin/ai/programminglanguage/add/`). Если «Тема не найдена» — заведите
тему (`/ai/admin/ai/topic/add/`) и привяжите её к языку. Команда печатает
список доступных вариантов.

После установки сигналы `Prompt` сами сбрасывают кэш каталога, поэтому промпт
сразу виден в селекторе — перезапуск контейнера не нужен.

## 3. Как студент получает промпт

1. Студент открывает `/ai/find-error/`.
2. Выбирает язык программирования (например, C-MPA).
3. Выбирает тему (например, «Одномерный массив»).
4. В селекторе «Промпт» появляется подходящий промпт. Если он единственный
   для этой пары язык+тема, он **выбирается автоматически** (JS
   `selectFirstIfSingle` в `static/admin/js/ai-common.js`).
5. Студент вставляет условие и код, отправляет.

Если промптов несколько, автоматического выбора нет — студент выбирает сам.
Если промпт не появляется:

- проверьте `mode="find_error"` у промпта;
- проверьте, что промпт привязан к выбранному языку и/или теме;
- проверьте, что тема принадлежит выбранному языку.

## 4. Правила C-MPA для одномерных массивов

Это ядро промпта. Модель должна проверять каждый пункт и объяснять нарушение.

### 4.1 Имена и глобальность

Все входные и выходные переменные/массивы из условия должны быть объявлены
**глобально, до `main`**, и называться **точно как в условии**.

```c
// Плохо: массив внутри main, имя другое
void main() {
    int mas[20];
    ...
}
```

```c
// Хорошо
int __bits(8) b[20];
int __bits(8) kol;

void main() {
    ...
}
```

### 4.2 Размер массива и `__bits`

- Размер массива — количество элементов из условия (`b[20]` — 20 элементов,
  индексы 0…19).
- `__bits(n)` — размер ОДНОГО элемента/значения, а не количество элементов.
- Если условие говорит «1 байт», «байтовые», «все переменные — байтовые», то
  нужен `__bits(8)`.
- Модификатор ставится между типом и именем.

```c
// Плохо: 1 бит вместо 8; и размер массива потерян
int __bits(1) b;

// Хорошо
int __bits(8) b[20];
```

### 4.3 Запреты при объявлении массива

- Нельзя `__in`/`__out` у массива.
- Нельзя присваивать массиву начальные значения при объявлении.

```c
// Плохо
int __in b[20];
int b[20] = {0};

// Хорошо
int __bits(8) b[20];
```

### 4.4 Инициализация и накопление

- Каждая переменная должна быть инициализирована до первого использования.
- Выходной переменной присваивается результат через `=`, а не `+=`.
- Выходную переменную нельзя обнулять ПОСЛЕ накопления (ответ всегда 0).

```c
// Плохо: kol не инициализирована; += вместо =; обнуление после цикла
kol += k;
kol = 0;

// Хорошо
int __bits(8) kol = 0;
...
kol = k;
```

### 4.5 Границы цикла

Для массива из `n` элементов цикл должен обработать ровно `n` элементов:

```c
// Плохо: 19 элементов вместо 20; выход за границу
for (i = 0; i < 19; i++) ...
for (i = 0; i <= 20; i++) ...

// Хорошо
for (i = 0; i < 20; i++) ...
```

### 4.6 `while`, `break`, `else if`

- В `while` условие выхода должно меняться (например, `i++`), иначе цикл
  бесконечный.
- `break` должен стоять в нужном цикле и не пропускать элементы, которые
  нужно обработать.
- Цепочка `else if` вместо независимых `if` — ошибка, если она мешает
  проверить каждый элемент по отдельности.

### 4.7 Элемент, а не весь массив

```c
// Плохо: сравнение всего массива
if (b < 4) ...

// Хорошо
if (b[i] < 4) ...
```

### 4.8 Условия и константы

- Оператор в `if` должен совпадать с условием задачи (`<`, `<=`, `>`, `>=`,
  `==`).
- Числовая константа — число, не символ: `if (b[i] < 4)`, а не `'4'`.

### 4.9 Формула и пример

Формула должна совпадать с условием. Обязательно проверьте её на примере
ввода/вывода из условия. Если пример не сходится — формула неверна, даже если
код синтаксически правильный.

### 4.10 `unsigned` и наличие массива

- `unsigned` допустим только там, где значения действительно не могут быть
  отрицательными; иначе нужен `int`.
- В задаче обязательно должен быть хотя бы один массив.

## 5. База ошибочных программ

База состоит из трёх уровней:

```text
Группа (одна задача/папка)  →  Ошибочная программа  →  Метки ошибок
FindErrorCaseGroup             FindErrorCase            FindErrorCaseLabel
```

- **Группа** хранит условие, `dl_node_id`/`dl_course_id`, язык и тему.
- **Программа** хранит код и статус (`draft` / `ready` / `verified` /
  `disabled`).
- **Метки** — коды из каталога (`ai/services/find_error_catalog.py`) и
  человекочитаемый текст ошибки.

### 5.1 Импорт из папки

```bash
python manage.py import_find_error_cases "Одномернный массив" \
  --dataset odnomerny_massiv \
  --language "C-MPA" \
  --topic "Одномерный массив" \
  --fetch-statements
```

Что читает команда:

- `1.mpc` — код (UTF-8);
- `error_*.txt` — метки (cp1251, код из имени файла);
- `url.txt` — `nid`/`cid` для DL;
- `info.txt` — условие, если DL недоступен.

Условие берётся по приоритету: локальная `Task` → DL (`fetch_task_info`) →
`info.txt`. Для DL нужен `--session-id` (DLSID).

Если языка или темы нет в БД, команда падает со списком доступных значений.
Флаг `--create-missing` создаёт отсутствующие `ProgrammingLanguage`/`Topic`
автоматически (по умолчанию — осознанное решение контент-владельца).

Повторный импорт идемпотентен: кейсы с тем же `source_hash` пропускаются,
поэтому ручные правки меток в админке сохраняются. Группа обновляется только
при реальном изменении полей; `statement_updated_at` меняется лишь тогда,
когда условие действительно поменялось. `--force` перезаписывает всегда,
`--dry-run` показывает план и откатывает транзакцию.

### 5.2 Ручное пополнение

Формы добавления короткие: технические поля импорта (`dataset`, `source_ref`,
`source_hash`, `statement_source`) админка заполняет сама, на добавлении они
не показываются (видны при редактировании в блоках «Импорт»/«Служебное»).

1. Откройте `/ai/admin/ai/finderrorcasegroup/add/` — создайте группу:
   название, язык, тема и, если задача есть на DL, `nid=`/`cid=` из её адреса.
   Условие вставьте вручную или оставьте пустым — его можно подтянуть из DL.
2. Откройте `/ai/admin/ai/finderrorcase/add/` — создайте программу:
   группа, название, код программы.
3. В блоке «Метки ошибок» добавьте строки: код из каталога и текст ошибки.
4. Поставьте статус `ready` (или `verified`, если проверили вручную).

Кнопка **«Загрузить условие из DL»** в списке групп/программ подтягивает
условие по `dl_node_id` от имени текущего администратора (нужен DLSID).

Ручные записи получают `dataset = manual` и `source_ref` вида
`manual/<название группы>` (у программы — `<source_ref группы>/<название
программы>`) — поэтому импорт их не ищет и не перезаписывает. При редактировании `source_ref`
можно поменять, но для записей из датасета делать это не нужно: по нему
импорт находит кейс.

## 6. Лаборатория промптов

Откройте **Промпты → Лаборатория промптов** (`/ai/admin/prompts/lab/`).

1. Выберите промпт: «По умолчанию» (общий `SharedPrompt`) или конкретный
   `Prompt` режима `find_error`.
2. Отметьте модели (2–3 достаточно для сравнения).
3. Выберите кейсы: группу, статус, поиск, «только с условием».
4. Оставьте включённым «Добавлять строку КОДЫ» — без неё метрики не считаются.
5. Нажмите «Запустить». Прогресс виден в «Процессах», страница обновляется
   автоматически.
6. Откройте прогон: сводка по моделям и сетка «кейс × модель».

### 6.1 Что такое строка `КОДЫ:`

Лаборатория дописывает в конец сообщения служебную инструкцию:

```text
В самом конце ответа добавь ровно одну строку:
КОДЫ: 3, 17
```

Это нужно для детерминированной проверки: лаборатория сравнивает найденные
коды с метками кейса. В production-промпт эта инструкция НЕ входит — студент
видит только человеческий разбор.

Если модель не вывела строку, результат считается «коды не найдены» (recall
падает), даже если в тексте разбора ошибка названа. Поэтому суффикс включён по
умолчанию.

### 6.2 Метрики

Для каждой пары «модель × кейс»:

- `expected` — коды из меток кейса;
- `parsed` — коды из строки `КОДЫ:`;
- `matched` — пересечение;
- `missed` — ожидались, но не найдены;
- `extra` — найдены, но не ожидались;
- `exact` — множества совпали полностью;
- `precision = |matched| / |parsed|`;
- `recall = |matched| / |expected|`;
- `F1 = 2 * precision * recall / (precision + recall)`.

Сводка по модели — micro-усреднение по всем кейсам (суммируем matched/parsed/
expected, затем считаем метрики). Отдельно показывается exact rate и recall по
каждому коду — так видно, какие ошибки промпт стабильно пропускает.

### 6.3 Как сравнивать версии

1. Запустите лабораторию на версии `v1` (например, 20 кейсов × 2 модели).
2. Скопируйте промпт в новый `Prompt` с именем `… (v2)` и измените текст.
3. Запустите тот же набор кейсов и те же модели на `v2`.
4. Сравните precision/recall/F1 и список пропущенных кодов. Не сравнивайте
   прогоны на разных наборах кейсов — это разные измерения.

Снимок промпта и точное отправленное сообщение хранятся в каждом результате,
поэтому старый прогон можно разобрать даже после правки промпта.

## 7. Типичные проблемы

| Симптом | Причина и что делать |
|---|---|
| Промпта нет в селекторе | Не тот `mode`, не тот язык/тема. Проверьте `mode="find_error"` и привязку. |
| Промпт не выбран автоматически | Для пары язык+тема больше одного промпта — выберите вручную. |
| Модель не выводит `КОДЫ:` | Включён ли суффикс? Не обрезан ли ответ? Проверьте `raw_response`. |
| Все коды `extra` | Модель поняла каталог иначе; проверьте формулировки в суффиксе и метки кейса. |
| `recall` низкий на одном коде | Посмотрите кейсы с этим кодом: возможно, промпт не покрывает правило. |
| DL 401/403 при импорте | Нет DLSID или нет доступа к курсу. Используйте `info.txt` (офлайн-фолбэк). |
| Условие пустое | Заполните `info.txt` или нажмите «Загрузить условие из DL». |

## 8. Правила изменения промпта

- Меняйте текст в `docs/prompts/find_error_cmpa_arrays.ru.txt`, затем
  `seed_find_error_prompt --force`. Не правьте только БД: при следующем сиде
  файл и БД разойдутся.
- Если правите в админке (быстрый эксперимент) — перенесите удачный текст
  обратно в файл.
- Не добавляйте в production-промпт каталог `error_N` и строку `КОДЫ:` —
  это служебная часть лаборатории.
- Не привязывайте промпт к одной задаче («Отчисление»), если он должен
  работать для всей темы.
- После изменения промпта прогоните лабораторию на одном и том же наборе
  кейсов и сравните метрики.
