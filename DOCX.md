## Инструкция для пользователя

1. Назначение инструкции
Инструкция предназначена для обычного пользователя AI-интерфейса (студента, преподавателя, любого авторизованного посетителя основного сайта). Она объясняет, как войти в раздел `/ai/`, выбрать режим работы и модель, отправить сообщение, работать с задачами по программированию, искать ошибки в коде и пользоваться голосовым режимом.
Важно. Обычный пользователь не управляет моделями, справочниками и настройками AI — он работает только с теми функциями интерфейса, которые доступны на текущую дату.

2. Доступ и вход
Отдельной регистрации в AI-интерфейсе нет. Авторизация передаётся из основной сессии сайта `dl.gsu.by` через cookie `DLSID`; при первом входе учётная запись создаётся в приложении автоматически (см. `ai/middleware.py`, `ai/external_account.py`).
    1. Войти на основном сайте `dl.gsu.by`.
    2. Перейти в раздел `/ai/`.
    3. Раздел откроется сразу; отдельный логин не требуется.
    4. Если доступ не открывается — заново войти на основном сайте и обновить страницу.
Адрес `/ai/` открывает последнюю активную вкладку (Чат, Реши задачу или В чём ошибка — выбор запоминается в браузере). Конкретный режим всегда можно открыть по прямым адресам:
Страница	Адрес	Назначение
Чат с DLAI	`/ai/chat/`	Свободный диалог с моделью.
Реши задачу	`/ai/solve-problem/`	Решение задачи по программированию.
В чём ошибка?	`/ai/find-error/`	Поиск ошибки в коде.

3. Как попасть в режим «Реши задачу» со страницы задачи
Режим «Реши задачу» обычно открывают не вручную, а ссылкой со страницы задачи на основном сайте: у задачи есть кнопка перехода в AI, которая ведёт на `/ai/solve-problem/?nid=<идентификатор задачи>`.
    1. Открыть задачу на основном сайте.
    2. Нажать ссылку/кнопку перехода в AI-раздел.
    3. Условие задачи автоматически подгрузится в поле ввода (приложение получает его через `/ai/api/task-info/`).
    4. Если текст задачи не подгрузился — вставить условие в поле ввода вручную и выбрать язык программирования.
Без параметра `?nid=` страница работает как обычный «решатель»: скопируйте условие задачи в поле ввода самостоятельно.

4. Общая структура интерфейса
Интерфейс состоит из верхней панели, центральной области сообщений и правой боковой панели.
Зона интерфейса	Элементы	Назначение
Верхняя панель	Переключатель страниц (Чат с DLAI / Реши задачу / В чём ошибка?), модель, сортировка моделей, язык интерфейса, тема оформления.	Определяет режим, модель и язык ответа.
Центр	Лента сообщений, поле ввода, кнопки Send и Clear Context.	Основная рабочая область диалога.
Правая панель	Ссылка «Админ-Панель» (видна ролям с правами).	Служебная навигация для администраторов и разработчиков промптов.

Дополнительные элементы верхней панели:
    • Тема оформления — переключение тёмной/светлой темы (запоминается в браузере).
    • «Последнее обновление: DD.MM.YYYY» — дата последнего задеплоенного обновления приложения (раздел «Обновления» админки).
    • Виджет лимитов моделей — для отдельных моделей показывает остаток суточных лимитов (токены/запросы).

5. Режим «Чат с DLAI»
Режим используется для свободного диалога: вопросы, объяснения, идеи, уточнения.
    • Поле ввода принимает обычный текст.
    • Кнопка Send отправляет сообщение; Enter отправляет, Shift+Enter переносит строку.
    • Пока модель отвечает, новый запрос не принимается — дождитесь ответа.
    • Ответы отображаются в виде аккордеона; последняя реплика раскрыта автоматически.
    • Блоки рассуждений модели (think-блоки) сворачиваются в отдельный аккордеон «Показать/Скрыть» — их можно раскрыть отдельно от основного ответа.
    • Clear Context очищает историю диалога и серверный контекст модели для текущей вкладки.
Когда нажимать Clear Context. Если модель начала учитывать старые сообщения, которые больше не относятся к новой задаче, очистка контекста помогает начать новый разговор без «хвоста» предыдущей темы.
История сообщений сохраняется в браузере (localStorage) и не пропадает после перезагрузки страницы; «Очистить контекст» не удаляет видимый чат, а сбрасывает память модели на сервере.

6. Режим «Реши задачу»
Режим предназначен для решения задач по программированию. Пользователь выбирает язык программирования, тему и, при необходимости, препромпт. Без выбранного языка программирования отправка блокируется.
Поле	Обязательность	Как влияет на запрос
Язык программирования	Обязательное	Добавляет контекст «реши задачу на языке …».
Тема	Зависит от языка	Уточняет учебный или технический раздел.
Препромпт	Необязательный	Задаёт стиль и глубину решения.
Текст задачи	Обязательный по смыслу	Условие, которое нужно решить (при входе через ссылку задачи подгружается автоматически).

Если выбрана тема, но препромпт не выбран, интерфейс спросит подтверждение — отправить ли запрос без препромпта.
Фактически система превращает сообщение в структурированный запрос «реши задачу на языке …» плюс выбранный препромпт, поэтому качество заполненных полей напрямую влияет на качество ответа.
Рекомендация. Формулируйте задачу полностью: входные данные, выходные данные, ограничения, примеры и требуемый формат ответа.

7. Режим «В чём ошибка?»
Режим предназначен для поиска ошибки в коде. Заполняются два поля — условие задачи и код программы, плюс язык, тема и препромпт. Должно быть заполнено хотя бы одно из полей: задача или код.
Поле	Что писать	Почему важно
Задача	Условие, ожидаемое поведение, примеры.	Модель понимает, что программа должна делать.
Код программы	Фрагмент или полный код с ошибкой.	Модель анализирует фактическую реализацию.
Язык программирования	Язык кода.	Без языка отправка блокируется.
Тема и препромпт	Контекст и формат разбора.	Помогают получить учебное объяснение, а не просто исправление.

Лучший запрос. Добавьте не только код, но и что именно пошло не так: ошибка компиляции, неверный ответ на тесте, зависание, превышение времени или неожиданное поведение.

8. Выбор модели
Модель выбирается в верхней панели перед отправкой сообщения. В списке отображаются только модели, доступные на текущую дату (доступность проверяется ежедневно в 04:00 МСК администрированием системы).
    • Группа «Часто используемые» — вверху списка стоит самая используемая модель именно вашего аккаунта (по истории успешных запросов).
    • Группа «Все модели» — остальные модели по алфавиту.
    • У каждой модели показываются средняя скорость ответа и процент успешных решений (по накопленной статистике).
    • Сортировку «Все модели» можно переключать: по алфавиту / по скорости / по точности / скорость+точность (запоминается в браузере).
    • Если ни одна модель сейчас недоступна, в списке отображается сообщение «Сегодня нет доступных моделей».
Совет. Модели отличаются по скорости и качеству: быстрые хороши для коротких вопросов, «мыслящие» (Thinking/Reasoning) — для сложных задач, но отвечают дольше.

9. Выбор языка интерфейса и ответа
Переключатель языка (Русский / English / Français) меняет подписи, плейсхолдеры и подсказки интерфейса. Кроме того, выбранный язык передаётся модели как инструкция отвечать на этом языке — на не-русских языках модель обязана отвечать только на выбранном языке, независимо от языка вопроса.

10. Встроенная инструкция «?»
В верхней панели есть кнопка «?» — она открывает окно «Инструкция пользователя» с этим самым текстом: инструкция всегда под рукой, искать её на сайте не нужно.
    1. Нажать кнопку «?» в верхней панели — откроется окно с инструкцией.
    2. Читать и прокручивать текст как обычную страницу.
    3. Закрыть окно: крестик ✕ в шапке окна, клавиша Esc или клик по затемнённому фону вокруг окна.
    4. Кнопка «⇓ Скачать .md» в шапке окна скачивает ту же инструкцию файлом.
Инструкция всегда показывается на том языке, который выбран в переключателе языка (Русский / English / Français). Поменяете язык при открытом окне — текст сразу перезагрузится на выбранном языке; если окно закрыто — откройте его заново после смены языка.
Инструкция обновляется сама: если её текст поправили на сервере, в открытом окне свежая версия появится в течение нескольких секунд — перезагружать страницу не нужно. При любом новом открытии окна показывается самая свежая версия.

11. Голосовой режим
Кнопка «Голосовой режим» открывает панель голосового ввода и озвучивания ответов. Работает в браузерах с поддержкой Web Speech API (обычно Chrome или Edge).
    • Голосовой ввод: надиктовать сообщение (запись до 30 секунд; распознанный текст отправляется автоматически).
    • Озвучить ответ: включить воспроизведение ответа модели голосом.
    • Стоп: прекратить озвучивание.
    • Опция «Озвучивать think-блоки»: проговаривать также служебные рассуждения.
Ограничение браузера. Если голосовые функции не работают, проверьте браузер, разрешение на микрофон и поддержку Web Speech API.

12. Работа с контекстом и форматирование кода
Контекст диалога помогает модели помнить предыдущие сообщения; это удобно в рамках одной темы и мешает при переходе к новой. Для нового обсуждения используйте Clear Context.
Код рекомендуется оборачивать в тройные обратные кавычки — ответ отображается читабельно и модель не путает код с обычным текстом:
```python
for i in range(5):
    print(i)
```

13. Практические примеры запросов
Ситуация	Пример хорошего запроса	Почему это хорошо

Реши задачу	Дана строка. Нужно посчитать количество гласных. Язык Python. Покажи алгоритм и код.	Указаны входные данные, цель и язык.

Формат ответа	Сначала кратко укажи ошибку, затем объясни причину и дай минимальное исправление.	Модель получает структуру ответа.

## Инструкция для разработчика промптов

1. Назначение и роль
Разработчик промптов — это роль для тех, кто создаёт и улучшает препромпты: управляющие инструкции, которые уточняют поведение модели (стиль, структуру, глубину разбора ответа). Роль доступна всем желающим: группа `prompt_developer` назначается автоматически каждому пользователю при первом входе через `DLSID` (см. `ai/external_account.py`).
Разработчик промптов работает в административном интерфейсе `/ai/admin/`, но имеет ограниченный набор прав: он управляет только своими промптами и видит только свои журналы запросов. Управление моделями, справочниками и глобальными настройками в его зону не входит.

2. Первый вход в админку
    1. Войти на основном сайте `dl.gsu.by`.
    2. Перейти на `/ai/admin/`.
    3. При первом входе система предложит установить локальный пароль на странице `/ai/admin/set-password/` (минимум 8 символов). Пароль нужен для внутренней идентификации в админке; авторизация по-прежнему выполняется через основную сессию.
    4. После входа в шапке отображается ваша роль — «Разработчик промптов».
Адреса, важные для разработчика промптов:
Раздел	Адрес	Что там
Мои промпты	`/ai/admin/prompts/my/`	Список только ваших промптов.
Все промпты	`/ai/admin/ai/prompt/`	Общий список промптов (правка — только своих).
Общие препромпты	`/ai/admin/ai/sharedprompt/`	Просмотр системных шаблонов (правка — только у персонала).
Журнал запросов	`/ai/admin/ai/airequestlog/`	Ваши запросы к моделям.
ARM: Пакетное решение	`/ai/admin/arm/solve/`	Пакетное решение задач DL выбранными моделями.
ARM: Поиск ошибки	`/ai/admin/arm/find-error/`	Прогон одной задачи через несколько моделей.

3. Мои промпты: создание и права
Раздел «Мои промпты» показывает только ваши промпты (владельцем или редактором которых вы являетесь; логика ACL — `ai/querysets.py::prompt_queryset_for_user`). Общий список промптов доступен через раздел «Промпты».
Права на промпт:
    • При создании промпта вы автоматически становитесь его владельцем (`owner`) и редактором (`editors`) — см. `ai/admin/models.py::PromptAdmin`.
    • Вы можете редактировать только свои промпты. Чужие промпты открываются в режиме «только чтение» (все поля readonly).
    • Удалить можно только свой промпт; суперпользователь может удалить любой.
    • Блок «Доступ» (владелец и список редакторов) настраивается только суперпользователем — он решает, кому дать право редактировать ваш промпт совместно.
Создание промпта:
    1. Открыть «Мои промпты» → «Добавить промпт».
    2. Заполнить поля (см. ниже) и сохранить.
    3. Промпт сразу появляется в выпадающем списке препромптов на страницах «Реши задачу» и «В чём ошибка?» — чат-интерфейс показывает все промпты всем авторизованным пользователям (препромпты — учебный контент, а не приватные данные).

4. Поля промпта
Поле	Назначение	Комментарий
Название (RU)	Как промпт отображается в списке.	Короткое и понятное, например «Разбор ошибки пошагово».
Язык программирования	Привязка к языку.	Определяет, в каких задачах промпт логичен.
Тема	Привязка к теме выбранного языка.	Используется для привязки «по теме».
Текст (RU)	Основной текст инструкции.	Главное поле; пишите конкретные инструкции модели.
Name/Text (EN, FR)	Переводы для не-русских языков интерфейса.	Заполняются автоматически (см. ниже).
Общий препромпт / Переопределение текста	Привязка к системному шаблону.	Настраивается персоналом; обычному разработчику промптов трогать не нужно.

Действия со списком промптов:
    • «Автоперевод → EN / FR» — заполняет пустые английские/французские поля через Google Translate (плейсхолдеры `{language}/{topic}/…` защищаются; сервис — `ai/services/auto_translate.py`).
    • «Экспорт выбранных промптов в CSV».
Качество текста. Хороший препромпт не подменяет задание пользователя, а уточняет способ ответа: формат, глубину объяснения, ограничения. Примеры — в разделе «Управление препромптами» инструкции суперадмина.

5. Общие препромпты: что это и почему их нельзя редактировать
«Общие препромпты» (`SharedPrompt`) — это не обычные препромпты, а системные шаблоны трёх режимов: чат, «Реши задачу», «В чём ошибка?». Именно из них собирается каркас запроса к модели, а выбранный пользователем промпт добавляется поверх. В шаблонах используются плейсхолдеры `{language}`, `{topic}`, `{message}`, `{code}`, которые приложение заполняет автоматически.
Разработчик промптов может просматривать общие препромпты, чтобы понимать, во что превращается его промпт, но редактировать их может только персонал (staff/superuser). Порядок настройки шаблонов и привязок — см. инструкцию суперадмина.

6. Как проверить свой промпт
Проверка через пользовательский интерфейс:
    1. Открыть «Реши задачу» или «В чём ошибка?» в чате.
    2. Выбрать язык, тему и свой препромпт.
    3. Отправить тестовый запрос и оценить ответ.
Проверка через ARM (сравнительное тестирование моделей):
    • «Поиск ошибки (ARM)» `/ai/admin/arm/find-error/` — прогон одной задачи (условие + код) сразу через несколько моделей: удобно сравнить, как разные модели соблюдают ваш промпт.
    • «Пакетное решение (ARM)» `/ai/admin/arm/solve/` — пакетное решение задач из курса dl.gsu.by выбранными моделями с отчётом по проценту решённых. Перед запуском можно задать необязательное название прогона (оно фиксируется в момент запуска и потом не меняется — по нему прогон удобно находить в журналах) и выбрать препромпт в списке.
    • Препромпт для ARM по умолчанию берётся из «препромптов по умолчанию» (привязок ARM) — их настраивает суперпользователь (см. `/ai/admin/prompt-defaults/`). Но привязка — не единственный способ: в списке «Препромпт» первая строка «По привязке (по умолчанию)» использует привязку, а любая другая строка — это ручной выбор конкретного промпта (подпись под списком показывает, какой препромпт реально применится). Проверяя промпт через ARM, убедитесь, что либо нужная привязка создана, либо промпт выбран в списке вручную.
Контроль результатов:
    • Журнал запросов `/ai/admin/ai/airequestlog/` показывает только ваши запросы: полный текст запроса, ответ модели, ошибку; доступны экспорт в XLSX и кнопка повторной отправки (resend).
    • Массовые прогоны в журнале показываются со статусом «Выполнен» или «Прерван»; если у прогона было название, оно видно в строках «Название прогона» (в развёрнутой записи, на странице деталей и в таблице «Последние пакетные решения» в «Настройке ИИ-приложения»).
    • В журнале есть поиск, фильтры по модели/статусу/режиму/дате и пагинация по 50 записей.

## Инструкция для тестера

1. Назначение и область применения
Документ описывает работу тестера в тест-панели и ARM-режиме 'В чем ошибка'. Основной сценарий — проверить одну задачу сразу в нескольких моделях и сравнить ответы по успешности, качеству, скорости, расходу токенов и корректности объяснения.
Инструкция предназначена для QA-специалистов и пользователей, включенных в группу `prompt_developer`. Она помогает проводить сравнение моделей одинаковым способом, чтобы результаты были воспроизводимыми.
Смысл ARM. ARM-тестирование снижает субъективность: одна и та же задача отправляется выбранным моделям, после чего ответы сравниваются по единым признакам.
У ARM есть два режима: «Поиск ошибки» (одна задача через несколько моделей — описан в этой инструкции) и «Пакетное решение» `/ai/admin/arm/solve/` (пакетное решение задач курса dl.gsu.by выбранными моделями с отчётом по проценту решённых). Оба режима доступны членам группы `prompt_developer`.

2. Доступ тестера
Для доступа пользователь должен входить в группу `prompt_developer` (группа назначается автоматически при первом входе через DLSID). После успешного входа пользователь автоматически направляется в ARM-раздел 'В чем ошибка'.
    1. Войти на основной сайт `dl.gsu.by` под своей учётной записью.
    2. Перейти на `/ai/admin/arm/find-error/`.
    3. Убедиться, что после входа открыт ARM-раздел 'В чем ошибка'.
    4. Если доступ запрещен, проверить членство в группе `prompt_developer`.

Пользователь в группе `prompt_developer`	Доступ к тест-панели открыт.	Обратиться к администратору прав.

Хороший тестовый кейс должен быть однозначным и воспроизводимым. Тестер должен указать условие, код, ожидаемый результат и тип ошибки. Если в кейсе недостаточно данных, разные модели могут давать разные ответы не из-за качества, а из-за неоднозначности исходных условий.

5. Выбор моделей и запуск отчета
Кнопка 'Запустить отчет' запускает последовательную проверку выбранных моделей. Последовательный запуск облегчает контроль ошибок, но увеличивает общее время выполнения при большом числе моделей.

    8. Заполнить задачу и/или код.
    9. Отметить модели для проверки.
    10. Нажать 'Запустить отчет' и дождаться формирования результатов.

## Инструкция для системного администратора

1. Назначение и контекст инфраструктуры
Документ описывает инфраструктурные требования и порядок запуска AI-приложения на виртуальной машине. Особое внимание уделено работе за корпоративным прокси, Docker/Docker Compose v2, PostgreSQL, портам, WebSocket и эксплуатационной диагностике.
Цель системного администратора — обеспечить воспроизводимый запуск, сетевую доступность сервиса, корректный доступ к внешним API моделей и предсказуемую диагностику при сбоях.
Главная особенность контура. VM не имеет прямого доступа в интернет: внешний трафик, включая docker pull и обращения к API моделей, должен идти через корпоративный прокси.

2. Требования к виртуальной машине

Сеть	Доступ к интернету через HTTP/HTTPS-прокси.	Проверяется отдельно для shell, Docker daemon и контейнеров.

3. Сетевой доступ и корпоративный прокси
Прокси должен быть настроен на тех уровнях, где выполняются сетевые обращения: shell/systemd, Docker Engine, сборка образов и, при необходимости, runtime контейнеров. Наличие прокси только в пользовательской shell-сессии не означает, что Docker daemon сможет скачивать образы.
3.1. Системный прокси
Системные переменные HTTP_PROXY, HTTPS_PROXY и NO_PROXY задают базовые правила выхода в сеть для командной оболочки и сервисов, которые наследуют окружение.
export HTTP_PROXY="http://user:pass@proxy.host:3128/"
export HTTPS_PROXY="http://user:pass@proxy.host:3128/"
export NO_PROXY="localhost,127.0.0.1,db,nginx,.local"

Пароли и спецсимволы. Если в логине или пароле есть специальные символы, их следует указывать в URL-encoded виде, иначе прокси может отклонять запросы.

4. Прокси для Docker Engine и сборки образов
Docker daemon является отдельным системным сервисом. Поэтому для скачивания образов прокси настраивается через systemd drop-in файл.
    1. Создать каталог /etc/systemd/system/docker.service.d.
    2. Создать файл http-proxy.conf с переменными окружения.
    3. Выполнить daemon-reload и перезапустить Docker.
    4. Проверить docker info | grep -i proxy.
sudo mkdir -p /etc/systemd/system/docker.service.d

# /etc/systemd/system/docker.service.d/http-proxy.conf
[Service]
Environment="HTTP_PROXY=http://user:pass@proxy.host:3128/"
Environment="HTTPS_PROXY=http://user:pass@proxy.host:3128/"
Environment="NO_PROXY=localhost,127.0.0.1,db,nginx,.local"

sudo systemctl daemon-reload
sudo systemctl restart docker
docker info | grep -i proxy

4.1. Прокси для build args
При использовании docker-compose.linux.yml переменные HTTP_PROXY и HTTPS_PROXY могут передаваться в секцию build args только на время сборки. Это полезно, если политика безопасности запрещает сохранять прокси в runtime окружении контейнеров.
5. Установка Docker и Docker Compose v2
Рекомендуется устанавливать Docker Engine из официального репозитория Docker, чтобы получить актуальные версии docker-ce и docker-ce-cli. После установки пользователя добавляют в группу docker, затем переподключают сессию.
sudo usermod -aG docker $USER

Права пользователя	docker ps	Команда выполняется без sudo при принятой политике доступа.

6. PostgreSQL и параметры подключения
PostgreSQL может размещаться на той же VM или быть внешним сервисом. Для production-подхода внешний PostgreSQL предпочтительнее: он проще резервируется, масштабируется и отделяет состояние от контейнеров приложения.
Параметр .env	Назначение	Контроль
DB_HOST	Адрес хоста PostgreSQL.	Доступен из контейнера web.
DB_PORT	Порт PostgreSQL, обычно 5432.	Не блокируется firewall.
DB_USER	Пользователь базы данных.	Имеет права на миграции.
DB_PASSWORD	Пароль пользователя.	Хранится безопасно, не публикуется в логах.
DB_NAME	Имя базы данных.	Существует до запуска миграций или создается регламентно.

Права БД. Пользователь PostgreSQL должен иметь права на создание таблиц и выполнение миграций. Иначе приложение может стартовать, но упасть на этапе инициализации схемы.

7. Подготовка .env и запуск контейнеров

# Сисадмин: инфраструктура и запуск

Этот документ дополняет базовые инструкции по развертыванию и описывает системные требования, прокси и нюансы виртуальной машины.

## 1. Контекст инфраструктуры

- Проект разворачивается на виртуальной машине (VM).
- VM находится за корпоративным прокси, поэтому для доступа к внешним API и скачивания образов нужен прокси.
- Основные зависимости на стороне сервера: Docker, Docker Compose v2 и PostgreSQL.

## 2. Требования к VM

- ОС: Linux (рекомендуется Ubuntu/Debian).
- Доступ к интернету только через прокси (HTTP/HTTPS).
- Открыт доступ к Docker daemon для пользователя (обычно группа docker).
- Свободные порты:
  - 8080 (dev-like) или 8081 (prod по умолчанию) для nginx контейнера.
  - 5432 для PostgreSQL (если БД на той же VM).

## 3. Настройка прокси

### 3.1. Системный прокси (если требуется)

Настройте переменные окружения на уровне shell или systemd:

- HTTP_PROXY
- HTTPS_PROXY
- NO_PROXY

Пример (в bash):

export HTTP_PROXY="http://user:pass@proxy.host:3128/"
export HTTPS_PROXY="http://user:pass@proxy.host:3128/"
export NO_PROXY="localhost,127.0.0.1,db,nginx,.local"

Если в логине/пароле есть спецсимволы, указывайте их в URL-encoded виде.

### 3.2. Прокси для Docker Engine

Если Docker должен выходить в интернет (pull образов), настройте прокси для демона.

1) Создайте каталог:

sudo mkdir -p /etc/systemd/system/docker.service.d

2) Создайте файл /etc/systemd/system/docker.service.d/http-proxy.conf:

[Service]
Environment="HTTP_PROXY=http://user:pass@proxy.host:3128/"
Environment="HTTPS_PROXY=http://user:pass@proxy.host:3128/"
Environment="NO_PROXY=localhost,127.0.0.1,db,nginx,.local"

3) Примените изменения:

sudo systemctl daemon-reload
sudo systemctl restart docker

4) Проверка:

docker info | grep -i proxy

### 3.3. Прокси для сборки образов

Если используется docker-compose.linux.yml, обратите внимание:
- В секции build args можно передавать HTTP_PROXY/HTTPS_PROXY только для сборки.
- В runtime переменные прокси могут быть отключены, если это нужно по политике безопасности.

## 4. Установка Docker и Compose

### 4.1. Docker Engine

Рекомендуемый способ (Ubuntu):

- Установить официальный репозиторий Docker.
- Установить docker-ce и docker-ce-cli.
- Добавить пользователя в группу docker:

sudo usermod -aG docker $USER

После этого перезайдите в сессию или выполните:

newgrp docker

Проверка:

docker version

### 4.2. Docker Compose v2

Проверка:

docker compose version

Если команда отсутствует, установите пакет docker-compose-plugin.

## 5. PostgreSQL

Варианты:
- Локальный PostgreSQL на той же VM.
- Внешний PostgreSQL (рекомендуется для отказоустойчивости).

Минимальные параметры подключения указываются в .env:

- DB_HOST
- DB_PORT (обычно 5432)
- DB_USER
- DB_PASSWORD
- DB_NAME

Убедитесь, что пользователь имеет права на создание таблиц и миграции.

## 6. Запуск контейнеров (рекомендованный порядок)

1) Создать .env и заполнить ключевые переменные.
2) Поднять стек:

docker compose --env-file .env up -d --build
docker compose --env-file .env exec -T web python manage.py migrate
docker compose --env-file .env exec -T web python manage.py collectstatic --noinput

Для прод-режима:

AI_NGINX_BIND=127.0.0.1 AI_NGINX_PORT=8081 docker compose --env-file .env up -d --build
docker compose --env-file .env exec -T web python manage.py migrate
docker compose --env-file .env exec -T web python manage.py collectstatic --noinput

3) Проверить статус:

docker compose ps

4) Проверить доступность:

curl -I http://127.0.0.1:8081/ai/chat/

## 7. Нюансы эксплуатации на VM

- Если VM не имеет прямого доступа к интернету, весь внешний трафик (API моделей, docker pull) должен идти через прокси.
- В случае 401/403/429 от моделей проверяйте:
  - валидность токенов в .env,
  - доступ к конкретной модели у провайдера,
  - корректность прокси (не подменяет ли ответы).
- Для WebSocket /ai/chat/ws/ убедитесь, что внешний nginx пропускает Upgrade и Connection: upgrade.

## 8. Диагностика

- Логи контейнера web:

  docker compose logs -f web

- Логи nginx:

  docker compose logs -f nginx

- Проверка статических файлов:

  curl -I http://127.0.0.1:8081/ai/static/admin/css/chat_template.css

## 9. Ротация и ресурсы

- Убедитесь, что на VM достаточно RAM (минимум 2-4 GB) и свободного диска.
- Для логов контейнеров используйте встроенную ротацию Docker или внешний logrotate.






## Инструкция для суперадмина

Эта инструкция написана для человека, который управляет всей ИИ-системой: включает и выключает её, выдаёт права, настраивает препромпты, смотрит, что происходило. Уметь программировать не нужно — всё делается в браузере нажатием кнопок.

### 1. Как войти

1. Зайди на сайт dl.gsu.by под своим обычным логином (как всегда).
2. Допиши в адресной строке браузера к адресу сайта `/ai/admin/` (получится примерно `https://dl.gsu.by/ai/admin/`) и нажми Enter.
3. Если ты входишь впервые — сайт попросит придумать пароль. Придумай и сохрани его.
4. Вверху страницы увидишь своё имя и роль. Если написано «Суперпользователь» — тебе доступно всё, что описано ниже.

Админка — это одна страница: слева меню, справа рабочая область. Между разделами переходишь ссылками в левом меню.

### 2. Шапка: «Процессы» и «Зайти как гость»

В верхней части страницы, рядом с приветствием, есть две важные кнопки.

**«Процессы (N)»** — список твоих запущенных проверок и прогонов. Нажми, чтобы посмотреть, как идёт текущая работа (например, пакетное решение задач). Завершённые процессы показываются ещё 10 минут.

**«Зайти как гость»** — показывает админку «глазами обычного пользователя»: часть разделов временно исчезнет из меню, и ты увидишь то же, что видит разработчик промптов. Это только вид — ничего не ломается и не отключается. Чтобы вернуть всё обратно, нажми ту же кнопку — она превратится в «Вернуться в полную админку».

### 3. Как включить и выключить ИИ (главный рубильник)

Самый первый пункт меню сверху — **«Настройка ИИ-приложения»** (⚙).

Выключить ИИ для всех:
1. Нажми «Настройка ИИ-приложения» в верху левого меню.
2. Сними галочку **«Включено»**.
3. Нажми «Сохранить» внизу страницы.

Сразу после этого у всех пользователей пропадёт доступ к ИИ — страницы будут показывать сообщение о выключении. Чтобы включить обратно — поставь галочку и сохрани. Это нужно при техработах, аварии у поставщика моделей или когда систему нужно временно «заморозить».

Важно: поле «Дата отсечки фаворитов» не трогай — оно служебное. Если случайно что-то там поменяли — попроси системного администратора восстановить.

Внизу этой же страницы — две удобные таблицы:
- **«Последние пакетные решения (5)»** — последние массовые прогоны моделей. У каждого прогона видно столбец **«Название прогона»** (то, что вписали в поле «Название прогона» при запуске; если названия не было — прочерк «—») и **«Статус»**: **«Выполнен»** (прогон дошёл до конца) или **«Прерван»** (его остановили или он не дошёл до конца). Клик по строке раскрывает подробные результаты — с переключателем «Все / Не пройденные», о котором написано в разделе 8.
- **«Последние запросы (5)»** — последние вопросы пользователей к ИИ; записи о массовых прогонах тоже попадают сюда, и статус у них тот же — «Выполнен» или «Прерван». Рядом ссылка на полный журнал.

Совет: перед плановым выключением ИИ предупреди пользователей и тестеров.

### 4. Права пользователей: как сделать человека Администратором или Суперпользователем

Роли в системе:

| Роль | Что умеет |
| --- | --- |
| Пользователь | Просто пользуется чатом. В админку не попадает. |
| Разработчик промптов | Может создавать и редактировать препромпты. Выдаётся автоматически каждому, кто вошёл в админку. |
| Администратор (staff) | Видит все разделы, все промпты, справочники, журнал запросов. |
| Суперпользователь | Всё то же самое плюс «опасные» разделы: рубильник ИИ, регрессионные тесты, тестовая консоль и выдача прав другим. |

Как выдать роль:
1. Открой список пользователей по адресу `/ai/admin/auth/user/` (эта страница не показана в меню — открой её по прямой ссылке, вписав адрес в браузер).
2. В поле поиска введи фамилию, логин или почту человека и нажми на его строку в результатах.
3. На странице пользователя найди блок **«Разрешения»**.
4. Поставь галочки:
   - **«Статус персонала»** — человек станет Администратором (видит почти всё).
   - **«Суперпользователь»** — человек получит полный доступ, включая выдачу прав другим.
   - **«Группы»** — список групп; обычно там уже есть «Разработчик промптов», ничего менять не нужно.
5. Нажми «Сохранить» внизу.

Два правила безопасности:
- «Суперпользователь» ставь только тем, кому действительно нужен полный контроль.
- Галочка **«Активный»** должна всегда стоять — если её снять, человек вообще не сможет войти.

Создавать пользователей руками не нужно: аккаунт появляется сам, когда человек первый раз входит через dl.gsu.by.

### 5. Права на препромпты: кто какой промпт может править

По умолчанию человек правит только свои препромпты. Если нужно разрешить править чужой — добавь его в «Редакторы» этого промпта. Два способа.

**Способ 1 — со страницы промпта:**
1. В левом меню открой «Раздел ИИ» → «Промпты».
2. Найди нужный препромпт (можно через поиск сверху) и открой его.
3. Раскрой свёрнутый блок **«Доступ»**.
4. В поле «Редакторы» начни вводить фамилию или логин — выбери человека из выпавшего списка.
5. Нажми «Сохранить».

**Способ 2 — со страницы пользователя (удобно, когда прав несколько сразу):**
1. Открой страницу пользователя (раздел 4, шаги 1–2).
2. Раскрой свёрнутый блок **«Права редактирования промптов»**.
3. Нажми «Добавить право на промпт», в строке выбери нужный препромпт (поиск работает по названию).
4. Нажми «Сохранить» внизу страницы.

Правило простое:
- свои промпты человек видит и правит всегда;
- чужие — только если он добавлен в «Редакторы» (правит, но удалить не может);
- Администратор и Суперпользователь видят и правят все промпты;
- удалить чужой промпт может только владелец или Суперпользователь.

### 6. Меню «Промпты»

- **«Мой препромпт»** — страница, где каждый разработчик промптов видит свои препромпты. Тебе она нужна, только если ты сам пишешь препромпты.
- **«Препромпты по умолчанию»** (только Суперпользователь) — задаёт, какой препромпт автоматически подставляется при массовой проверке задач (ARM) для конкретного языка и темы. Здесь создаются связки: язык + тема → препромпт. Без связки ARM-проверка идёт «с пустым» препромптом.

### 7. Меню «Документация»

Здесь лежат инструкции (эта в том числе). Каждая открывается страницей с текстом, а сверху есть кнопка «⇓ Скачать .md» — скачать файлом.

Страницы документации обновляются сами: если файл с инструкцией поправили прямо на сервере, на уже открытой странице новая версия появится через несколько секунд — ничего перезагружать не нужно. При обычном открытии страницы тоже всегда показывается самая свежая версия.

- **«Разработчик промптов»** — доступна всем, кто попал в админку.
- **«Разработчик»** — для Администраторов и Суперпользователей.
- **«Суперюзер»** — только для Суперпользователей.

### 8. Меню «ARM» — проверка моделей

- **«Пакетное решение»** — массовая проверка: выбираешь задачи, модели, язык, тему и препромпт; система прогоняет каждую задачу через каждую выбранную модель, проверяет ответы через dl.gsu.by и показывает, какие модели решают задачи хорошо, а какие — нет. Результаты можно выгрузить в Excel. Пошаговая инструкция — ниже в этом же разделе.
- **«Состояние моделей»** — таблица: какая модель работает прямо сейчас, а какая нет. Неактивная модель скрыта от пользователей. Если данные кажутся старыми — нажми кнопку обновления на этой странице и подожди немного.

Приложение и само проверяет модели — раз в день рано утром. Если какая-то модель сломалась, она часто восстанавливается сама после перепроверки.

#### Пакетное решение: как запустить прогон

Форма на странице — это несколько блоков сверху вниз. Заполняй по порядку:

1. **«Задачи из дерева DL»** — впиши course_id курса (номер курса — в адресе страницы курса на dl.gsu.by) и нажми кнопку **«Загрузить дерево»**: появится список задач курса. Папки в нём сворачиваемые — раскрой нужные и отметь галочками задачи. Есть галочка **«Выбрать всё дерево»** — отметит всё сразу.
2. **«Модели»** — отметь галочками модели, которые будут решать задачи (есть кнопка-галочка «Выбрать все модели»). Если не отметить ни одной, прогон пойдёт по всем доступным моделям.
3. **«Язык программирования»** — обязательно выбери язык из списка (до выбора стоит строка «— выберите язык —»). Без языка прогон не запустится.
4. **«Тема»** — выбери тему, если нужно: она подставляется в препромпт.
5. **«Препромпт»** — инструкция, с которой модели будут решать задачи:
   - Первая строка списка — **«По привязке (по умолчанию)»**: будет использован препромпт из «Препромптов по умолчанию» (связка «язык + тема», их настраивает Суперпользователь — см. раздел 6).
   - Любая другая строка — твой ручной выбор конкретного препромпта, он действует вместо привязки.
   - Прямо под списком сразу показано, какой препромпт реально применится: «Препромпт по умолчанию: …», «Препромпт (выбран вручную): …» или «Препромпт по привязке не задан — прогон без препромпта».
   - Твой выбор запоминается в браузере: вернёшься на страницу — выбор останется.
6. **«Название прогона»** — необязательное поле (до 200 символов), пример уже вписан в само поле: «Проверка новых задач, неделя 3».
   Важно: название даётся один раз — в момент запуска. После запуска его не переименовать: оно навсегда останется в «Настройке ИИ-приложения» и в журнале запросов, и по нему всегда понятно, что это был за прогон. Без названия тоже можно — у такого прогона в списках будет прочерк «—».
7. Нажми кнопку **«Запустить пакет»**. Прогон сразу появится в меню «Процессы» и пойдёт сам. Страницу можно не закрывать — прогресс и результаты появятся на ней; можно и закрыть — результаты останутся и откроются позже (см. таблицу «Последние пакетные решения» в разделе 3 или журнал запросов). Кнопка **«Прервать тестирование»** останавливает идущий прогон — в журналах такой прогон получит статус «Прерван».

#### Пакетное решение: как читать результаты

Когда прогон закончится, на странице появятся две карточки.

Первая — **«Сводка»**: сколько всего пар «задача × модель», сколько решено / не решено / пропущено, сколько потрачено токенов, итоги по каждой модели и по темам. Кнопка **«Скачать результаты (XLSX)»** выгружает всё это в Excel.

Вторая — **«Ответы моделей»**: список карточек, по одной на пару «задача + модель». У каждой карточки метка: зелёная «Решено», красная «Не решено» или серая «Пропущено». Открой карточку кликом — увидишь итог DL-теста, полный ответ модели и извлечённый из ответа код (рядом кнопка «Скачать код»).

В шапке карточки «Ответы моделей» стоит переключатель из двух кнопок: **«Все (N)»** и **«Не пройденные (M)»** — в скобках показано, сколько карточек будет при каждом выборе.

- **«Все (N)»** — показаны все карточки.
- **«Не пройденные (M)»** — показаны только не пройденные: «Не решено» или «Пропущено». Самый быстрый способ увидеть ошибки.

Как работает переключатель:
1. Нажми «Не пройденные (M)» — останутся только не пройденные карточки, и они раскроются сами: видно, что именно модель сделала не так, без клика по каждой карточке.
2. Нажми «Все (N)» — вернётся полный список, и карточки примут тот же вид, что был до переключения (что было раскрыто — то и раскрыто).
3. Выбранный режим запоминается в браузере: откроешь результаты снова — фильтр будет каким ты его оставил. Это работает на всех страницах, где рисуется эта таблица: в «Пакетном решении», в развёртке строки в «Настройке ИИ-приложения» и в детальной странице записи журнала.
4. Если не пройденных нет ни одной — кнопка «Не пройденные (0)» становится неактивной (нажать нельзя), и список остаётся в режиме «Все».

### 9. Меню «Диагностика»

- **«Журнал запросов»** — полная история: кто, когда, что спрашивал у ИИ, какая модель отвечала и чем закончилось. Клик по строке открывает полный вопрос и полный ответ. Есть фильтры, поиск и выгрузка в Excel. Это главный инструмент для разбора ситуации «у пользователя что-то было не так».

Массовые прогоны тоже записываются в журнал, и их легко отличить:

- Статус такой записи — **«Выполнен»** или **«Прерван»**. Это судьба всего прогона, а не одного запроса: «Выполнен» — прогон дошёл до конца, «Прерван» — его остановили или он не дошёл до конца. Пока прогон ещё идёт, статус «Выполняется…».
- В развёрнутой записи есть блок **«Прогон»** с двумя строками: **«Название прогона»** (если при запуске задали название — здесь оно; иначе «—») и **«Статус прогона»**.
- На отдельной странице записи (клик по строке журнала, страница с полным текстом) в шапке тоже показаны «Статус» и «Название прогона» — сразу понятно, чей это прогон, не читая весь ответ.

Как читать результаты самого прогона — раздел 8, «Пакетное решение: как читать результаты» (там же про переключатель «Все / Не пройденные»).
- **«Регрессионные тесты»** (только Суперпользователь) — автоматическая проверка препромптов: система прогоняет заранее подготовленные вопросы и показывает, совпадают ли ответы с ожидаемыми. Используется, прежде чем «выпускать» изменённый препромпт в работу.
- **«Тестовая консоль»** (только Суперпользователь) — проверка всего сайта в один клик: нажми «Запустить» и дождись сводки. Зелёная сводка — с сайтом всё в порядке. Второй прогон одновременно запустить нельзя — дождись окончания первого.

### 10. Меню «Система»

- **«Обновления»** — история изменений сайта: что, когда и кем менялось. Удобно открыть, чтобы понять, обновлялся ли сайт и что именно в нём поменялось.

### 11. «Раздел ИИ» — основные хранилища

Ниже групп инструментов в меню находится «Раздел ИИ» — основные списки данных:

- **«Промпты»** — все препромпты (про права — раздел 5).
- **«Общие препромпты»** — базовые шаблоны, из которых собираются препромпты. Правка здесь отражается сразу на всех связанных препромптах — будь осторожен.
- **«Языки программирования»** — список языков (Python, C++ и т.д.).
- **«Темы»** — темы внутри языков. Кнопка «Автоперевод → EN / FR» заполняет недостающие переводы автоматически.
- **«Внешние учётные записи DL»** — технический список связок «аккаунт сайта ↔ аккаунт dl.gsu.by». Нужен редко: чтобы убедиться, что конкретный человек корректно подключился. Для каждой записи видно имя, логин и учебные данные студента из dl.gsu.by: email, форма обучения, школа, группа и класс — они подтягиваются автоматически, когда человек входит на dl.gsu.by (у записей, откуда данные ещё не пришли, стоит прочерк «—»).
- **«Задачи»** — список учебных задач (страница не показана в меню; прямая ссылка `/ai/admin/ai/task/`). Кнопка «Обновить название и условие из DL» подтягивает свежие данные с dl.gsu.by.
- **«Пользователи»** — все аккаунты (прямая ссылка `/ai/admin/auth/user/`; как выдать права — раздел 4).

### 12. Типовые ситуации: что делать

| Ситуация | Что делать |
| --- | --- |
| Нужно выключить ИИ | Раздел 3: снять «Включено», сохранить. |
| Пользователь говорит: «модель недоступна» | «Состояние моделей» → нажми обновление → посмотри статусы. Модель неактивна — обычно восстановится сама после перепроверки. |
| Пользователь спрашивает, что отвечал ИИ | «Журнал запросов» → найди его запрос (поиск) → клик по строке: полный вопрос и ответ. |
| Коллега должен править чужой препромпт | Раздел 5: добавь его в «Редакторы». |
| Сделать человека Администратором | Раздел 4: галочка «Статус персонала». |
| Изменили препромпт и нужно проверить, что он не испортился | «Регрессионные тесты» → запустить прогон. |
| Просто убедиться, что сайт цел | «Тестовая консоль» → «Запустить» → дождаться сводки. |
| Посмотреть, что недавно менялось на сайте | «Обновления». |

### 13. Если что-то не работает — порядок действий

1. Открой **«Состояние моделей»**, нажми обновление: если модель неактивна — дело в ней, обычно она восстановится сама.
2. Открой **«Журнал запросов»** и найди проблемный запрос — в детальном просмотре будет причина (ошибка, время, модель).
3. Запусти **«Тестовую консоль»** — она покажет, цел ли сам сайт.
4. Если модель не восстанавливается или ошибка повторяется — сообщи системному администратору (он отвечает за ключи, прокси и сервер).

Полезно помнить: приложение умеет восстанавливаться само. Если у всех пропали модели, при первом же открытии чата запускается автоматическая перепроверка — часто достаточно просто подождать пару минут.

## Инструкция для разработчика

1. Назначение и область применения
Эта инструкция предназначена для разработчиков, которые вносят изменения в код DL.AI. Она описывает архитектуру, порядок локальной разработки, ключевые подсистемы, тестирование и соглашения по работе с репозиторием. Полная техническая документация находится в файле [doc/Документация для разработчика.md](doc/Документация%20для%20разработчика.md).

2. Требования к окружению
Для локальной разработки без Docker нужны Python 3.11+, PostgreSQL 14+ и psql. Для Docker-разработки достаточно Docker Engine, Docker Compose v2 и свободных портов 8080 (dev) или 8081 (prod).

3. Локальный запуск без Docker
    1. Создать базу и пользователя PostgreSQL.
    2. Скопировать .env.example в .env и выставить DB_HOST=127.0.0.1.
    3. Создать виртуальное окружение, установить зависимости, выполнить миграции.
    4. Запустить python manage.py runserver 0.0.0.0:8000.
    5. Открыть http://127.0.0.1:8000/ai/...

4. Локальный запуск в Docker
    1. Скопировать .env.example в .env и выставить DB_HOST=db.
    2. Запустить docker compose --env-file .env up -d --build.
    3. Выполнить миграции и collectstatic внутри контейнера web.
    4. Открыть http://localhost:8080/ai/...

5. Git workflow
    1. Каждый разработчик работает в отдельной ветке, названной по фамилии.
    2. По готовности открывается Pull Request в main.
    3. PR проверяется и мерджится в main.
    4. Изменения выкатываются на production.

6. Архитектура и ключевые подсистемы
Компонент	Назначение	Что важно для разработчика
Django + Channels	Основное приложение и WebSocket.	Все изменения — в единственном приложении ai.
ExternalAuthMiddleware	Проверка сессии DLSID на dl.gsu.by.	Локально можно использовать тест-панель входа по паролю.
Prompt / SharedPrompt	Препромпты и общие шаблоны.	Поддерживаются плейсхолдеры {language}/{язык}, {topic}/{тема}, {message}, {code} и локализация ru/en/fr.
WebSocket consumer	Обработка чата, решения задач, поиска ошибок.	Приходит JSON с type, message, value, progLng, topic, preprompt, code.
Model clients registry	Выбор провайдера по ключу модели.	Каталог по умолчанию: Ollama (облачные модели), OpenRouter (бесплатные модели, скрыты из селекторов), Web DeepSeek и Web Kimi (Puppeteer bot pool'ы в одном контейнере на :3000/:3001). Groq и SambaNova включаются флагами AI_ENABLE_GROQ / AI_ENABLE_SAMBANOVA. Новые модели регистрируются в ai/model_clients/registry.py.
AIRequestLog	Логирование всех запросов.	Каждый запрос и ARM-прогон записываются в лог.
Bot pool	Web DeepSeek и Web Kimi через Puppeteer.	Сервисы в WebDeepseek/ (:3000) и WebKimi/ (:3001, отдельное KIMI_* окружение, ручной seed-логин); документация пула — docs/web_deepseek_bot.md.
Model health	Ежедневная проверка доступности моделей.	Запускается автоматически в 04:00 МСК; можно отключить AI_DISABLE_HEALTH_SCHEDULER=1.

7. Логи запросов
Раздел /ai/admin/ai/airequestlog/ доступен staff/superuser. По клику на строку таблицы открывается страница деталей /ai/admin/ai/airequestlog/<id>/, где показаны полный запрос, ответ модели и техническая ошибка. Inline-разворачивание в списке не используется.
